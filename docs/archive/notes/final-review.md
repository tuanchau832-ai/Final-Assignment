# Independent implementation review

Reviewed the implementation snapshot and checked the current source against blueprint 03–07. Locations below refer to the revision under review on 18 November 2026, before the coordinating agent's fixes. This was a source review. The coordinating agent owns execution and regression verification.

## Critical

1. **The frontend Docker build is missing its registry inputs.** `Dockerfile:2–6` copies only `frontend/` before `npm run build`. The relative imports in `frontend/src/common.tsx:6` and the sensor registry import resolve to `/build/shared/registry`. The local checkout provides these JSON files but the Node image stage does not. Copy `shared/registry/` to that path before building, and verify the Node stage from an empty image cache when available.

## Important

1. **A retry can end the active boot and clear its alerts.** `backend/app/service.py:139–157` supersedes the active session, opens another, and clears sensor rule state before checking duplicate identity or timestamp bounds. A duplicate from an earlier boot can become the station's current session, although the ack reports zero accepted frames and the station version stays constant. A first batch of only rejected timestamps also claims an unused station. The freshness monitor at line 202 skips that station indefinitely because it has no last frame. Classify frames before ownership changes, preserve the original session for historical data, and add old-boot duplicate and first-batch rejection regression cases.
2. **A dashboard left open freezes its charts and timeline.** `frontend/src/DashboardPage.tsx:10` stores the upper bound once per selected range. Later history and timeline polls fetch the same closed interval. A new replay can change the live sensor cards while no corresponding points or events appear. Move the range with server-adjusted time and merge the latest snapshot sample into the live chart tail as specified in blueprint 05, guarantee G6.
3. **An alert detail can submit a different alert's review and display staff-only cache after logout.** `frontend/src/AlertsPage.tsx:8,15–16` preserves the local review ID on a detail-to-detail URL change and falls back to it when the new alert has no review. Key the detail by alert ID or rely on the review attached to the currently displayed alert. The same component renders cached event actors and notes regardless of authentication. `frontend/src/api.ts:23,31` keys alert detail only by ID and invalidates on mutation. A failed, pending, or disabled refetch can leave private text visible after logout. Clear or partition authenticated detail data and gate private event fields by authenticated identity. The alert API itself strips public notes and actors, and review endpoints enforce staff roles.
4. **Replay controls become unusable after natural completion.** `frontend/src/SimulationPage.tsx:24,31` sets a local run ID at start and clears it only after successful manual stop. Natural completion removes the run from the server, so Stop returns 404 and Start stays disabled. The ID also follows the user between station choices, where Stop can affect the wrong station. Derive controls from the selected station's current, non-ended replay session and reconcile any optimistic state at poll time.
5. **The state ETag does not describe all visible durable changes.** Review operations in `backend/app/main.py:186,258,278,286` modify `open_alerts` or `open_alert_count`. Session end in `backend/app/main.py:368` or `backend/app/service.py:212` changes the snapshot's session. These paths do not advance the station version underlying the ETag at `backend/app/main.py:100`. A cache can receive a 304 indefinitely during an offline interval. Advance affected stations once per committed snapshot-changing transaction, with a conditional-GET regression after closure on an idle station.
6. **Replay takeover and cancellation can race with writers.** `backend/app/main.py:333–355,361–370` discovers a prior scheduler before awaiting its cancellation, then releases the station lock between ending the old session and inserting the first replay frame. Multiple concurrent takeover requests can therefore act on different current owners than the task originally discovered. Cancellation of an `asyncio.to_thread` await does not cancel or necessarily join the underlying ingest, which can still take its turn after stop or reset. Serialize start/stop per station, wait for an in-flight ingest before releasing ownership, and atomically create or reserve the session for a known boot. Include overlapping starts, stop during ingest, and a live upload during takeover in the regression cases.
7. **A sequence of historical faulty readings fabricates an immediate clearance.** `backend/app/service.py:171–184` clears each active historical episode at the measurement time immediately after evaluation, even if that reading just opened the episode. Its historical counter then retains `active=true` for that already-cleared alert. The public incident record reports a zero-duration fault even when additional backfilled frames establish a sustained condition. Use the actual historical clear condition and reconcile with the next known measurement when returning to the live time boundary. Reset session-specific historical counters on boot and on demo reset, as well as live counters.

## Other observations

- `backend/app/main.py:117–118` subtracts a token before rejecting a request. Repeated throttled requests can drive the balance negative and prolong recovery beyond the advertised retry interval. Debit accepted requests only. Failure-counter and bucket maps should also prune expired entries.
- `backend/app/main.py:39` enables the startup TLH loop solely through `REPLAY_TLH_ENABLED`. Blueprint 07 also assigns `DEMO_MODE` control over automatic looping. `backend/app/service.py:206–209` always opens `STN_OFFLINE` even when an administrator disabled that rule. The station should still go offline, while alert creation should follow the rule's enabled setting.
- `frontend/src/ModelCanvas.tsx:15–29` handles exact mesh names and attaches selection to those meshes. The blueprint's registry-coordinate hotspot fallback for a missing/merged sensor node is absent. An otherwise loadable GLB can therefore be displayed with unselectable, uncoloured sensor heads. The whole-asset 2D fallback and sidebar still work. Registry-coordinate markers or an explicit switch to the schematic upon detecting missing required nodes would make a partial asset failure visible.
- `frontend/src/api.ts:17` and the model/dashboard use one canonical station snapshot, which is consistent with the exhibit's core synchronisation requirement. The ingest transaction, database frame uniqueness, server-derived provenance and simulated-only review outcomes give the happy path a coherent design. Many business rules and UI screens are compressed into single large lines. Extracting transaction-level operations and UI controls would make future state and authorization regressions substantially easier to identify.

The source implements the local ingest, simulated scenarios, role-based review, firmware protocol, and a model-independent interface. Full blueprint acceptance still needs the fixes above and separate integration evidence. The outstanding user model, public Wokwi project and cloud credentials were not counted as source defects.
